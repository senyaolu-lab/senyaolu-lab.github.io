03

打开就出店 不需要点任何按钮

Auto Load
1定位微信 GPS（真机最准）→ 失败自动退到 IP 定位
2立即出店内置数据 / 缓存 0ms 返回，界面马上有东西可摇
3后台刷新联网拉最新数据，不阻塞界面，下次进来就是新的
4逐级兜底内置 → 缓存 → 我的店池 → 引导用地图选店

崂山区内置数据

从 OpenStreetMap 抓取并清洗出的崂山区真实店铺，按距离排序内置进小程序。 人在崂山区附近时秒开；离开这个范围会自动忽略，不会推荐外地的店。

地图选店（全国通用）

点「地图选店」从腾讯地图点一家店，返回的店名就是腾讯地图 POI。 系统自动判定类型、菜系、是否可外卖，一次点击直接入库。

位置漂移保护

缓存只在离当前位置 3km 内才用；内置数据只在离崂山区中心 25km 内才用。 这条有专门的自动化测试守着。

03+

断网能用吗 说清前提，不含糊承诺

Offline

✓ 断网真的能做到

  • 摇出结果：内置 140 家 + 你存的店，三种随机方式全部可用（纯本地计算）
  • 切换半径 / 外卖 / 进店：本地过滤，不联网
  • 美食栏浏览：完整可用
  • 连定位都没有时：直接把内置数据当「崂山区列表」端出来，不会是空屏

✗ 断网做不到

  • 导航 —— 需要地图瓦片
  • 「去美团搜这家」—— 需要跳转外部 App
  • 拉取崂山区以外的店 —— 内置数据只有崂山区
  • 第一次打开小程序本身 —— 需先从微信服务器下载

三层定位回退

1GPS微信原生定位，不需要网络。实测出店 140 家
2IP 定位GPS 被拒时退到这里。需要网络，断网时会失败
3无定位兜底把内置数据当默认列表，距离标注「相对崂山区中心」
✓结果三层全覆盖，实测不会出现空屏
这里修过一个真缺陷：最初版本的「无定位」路径直接返回失败提示 —— 意味着「全新安装 + 断网 + 拒绝定位权限」的用户会看到一片空白，那「断网能用」就是假的。 现在改成：没有位置也把内置数据端出来，并把距离口径明确标注，不假装那是精确距离。 这条有 19 项离线测试守着。
05

数据来源与工程质量

Under the Hood
定位 微信 wx.getLocation 网络定位 ipwho.is → api.ip.sb 店铺 OpenStreetMap (ODbL) 地图选店 腾讯地图 POI 反向地理编码 三级降级

不做什么

不读取美团 / 饿了么 / 高德的数据。 小程序运行在微信沙箱里，读不到其它应用的数据；外卖平台也没有公开接口， 且小程序强制 HTTPS + 域名白名单，爬虫方案在真机上必然失败，也违反平台条款。
不编造评分和人均价格。 OpenStreetMap 没有这两个字段，就照实只显示距离和菜系。 要看真实评价，用「去美团搜这家」复制店名，切到 App 粘贴搜索。 宁可少给，不给假数据。

踩过的坑（都已修复并加了测试守护）

坑现象与处理
HTTP 定位真机失效 ip-api.com 的 HTTPS 端点已不可用，而小程序真机强制 HTTPS → 改为 ipwho.is 两级降级
微信 UA 被镜像拒绝 wx.request 不允许设置 User-Agent，微信强制注入自己的 UA， 而多数 Overpass 镜像对微信 UA 返回 406 → 镜像按实测可用性重排，只留能用的
Overpass 返回错误页 实测同一查询三次里两次返回 HTTP 504 + text/html 的 XML 错误页 → 按状态码 + content-type 双重校验，退避重试 + 换镜像
中文店名被误杀 JS 里 \W 把所有中文当非单词字符，导致中文店名全被过滤掉 → 改用显式字符类判断（guess_test 里 30 个真实店名守着这条）
「星巴克」推断不出咖啡 它是 Starbucks 的音译，字面里没有"咖啡"二字 → 菜系规则补入品牌词，并把泛匹配（如"冰"）降权，避免「蜜雪冰城」被抢成冰品
