产品与策略作品案例 PRD
GrowthPilot 广告策略助手 / FlowDesk Agent 任务工作台
版本：1.0 · 2026-11-01
性质：独立概念作品，AI 辅助设计与实现。不是字节跳动或其他企业的官方产品、内部项目或委托成果。

一、作品目的与证据边界

以可运行的产品原型展示：业务问题拆解、广告指标理解、可解释策略、实验设计、Agent 任务流程、工具边界、异常恢复与验证能力。
所有品牌、素材、金额与经营数据均为合成示例。没有实际用户访谈、真实投放、线上转化提升、生产级模型接入或客户使用记录。
本作品针对广告策略 / AI 产品 / Agent 产品方向建立能力证据，未宣称逐项对应某条已核验官方 JD。
当前提供规则模拟原型：纯 HTML / CSS / JS，浏览器即可运行；没有第三方依赖和外部 API 请求。核心逻辑与 Node 评测共用 product-core.js。

二、共同问题假设

H1：初级投手在数据面板与动作之间缺乏结构化判断流程。
H2：商家以经营目标描述任务，而非按组织模块提出需求。
H3：不透明的自动执行会降低用户信任；可见计划、证据与授权边界可以帮助用户理解结果。
上述均为待验证假设，不是访谈结论。
计划验证：招募 5 位目标用户，完成“找出异常 → 解释证据 → 选择下一步”的任务；记录完成情况、错误判断、追溯行为和授权理解情况。该计划尚未实施。

三、GrowthPilot 范围

目标用户：假设中的初级投手、小团队电商运营负责人。
目标任务：判断一组素材为何变化，生成受预算约束的下一周期草案，并制定可验证的实验。
信息架构：情景 → 目标与预算 → 核心指标 → 原始证据 → 诊断建议 → 预算草案 → 实验计划。

功能 P0
1. 四类合成广告情景：新品冷启动、素材疲劳、承接页异常、稳定期扩量。每类 3 条当前与上一周期记录。
2. 展现、点击、转化、消耗、收入可逐项回查。
3. 总量加权指标：CTR=总点击/总展现；CVR=总转化/总点击；CPA=总消耗/总转化；ROAS=总收入/总消耗。
当前示例把转化定义为发生购买的归因点击，一次点击最多计一次转化；套装与单品的客单价可以不同。
4. 零分母返回 null，显示“—”；拒绝负数、非有限数和逆序漏斗。
5. 下周期预算 8000–40000 元，收入回报优先 / 转化成本优先，CPA 风险线 20–300 元。
6. 每条建议展示观察、可验证动作、证据 ID 与不确定性。页面最多显示 3 条，导出保留完整诊断。
7. 下载 JSON：情景、原始数据、输入约束、指标、诊断、预算草案与限制。
8. A/B 样本量估算：基准 CVR、相对 MDE、双侧 alpha 0.05、power 约 0.80。

规则与重要取舍
预算基准=总预算×素材历史消耗占比；按目标排序，在最优与最差素材间转移 min(最优基准×20%, 最差基准×20%)；保持总预算守恒且每项相对基准变化不超过 ±20%。
这是透明、有限的启发式，不是最优投放算法。CPA 输入是风险标记，不保证新周期达标。不得将参考分配包装成收益承诺。
诊断阈值：CTR 低于上一周期 75% 时提示点击下滑；CVR 低于上一周期 65% 时提示承接问题；历史 CPA 高于目标则标记成本风险。
阈值属于作品规则，未通过真实广告数据校准。创意疲劳、库存、页面加载、价格、竞价与归因延迟都可能是候选原因。
收入未扣退款、履约或商品成本；ROAS 不等于利润率。

实验设计
p1=p0×(1+相对MDE)，pbar=(p0+p1)/2。
n/组=ceil([1.96×sqrt(2×pbar×(1-pbar))+0.84×sqrt(p0×(1-p0)+p1×(1-p1))]^2/(p1-p0)^2)。
前提：两组独立、随机分流、固定观察窗口与归因口径，足够计数。近似计算未考虑群组随机、重复曝光、转化延迟与多重检验。
保护指标：CPA、投诉率、异常退款；实验期间固定主指标，不因反复观察 p 值而提前停止。
核心模块另提供两比例 z 检验用于规则层测试，稀疏计数会标记近似不可靠。

GrowthPilot 验收
- 4 个情景都能切换，原始值与指标同步。
- 非法输入有明确提示，禁止导出过期草案。
- 预算守恒，单项调整边界成立；目标策略冲突时资金流向可以改变。
- 建议证据 ID 在选中情景中存在。
- MDE 降低时，所需样本量上升。

四、FlowDesk 范围

目标用户：假设中的商家经营者、运营负责人。
目标任务：围绕经营问题创建一次任务，查看计划与工具轨迹，处理失败，审核草案，导出结果。
信息架构：任务输入 / 预设目标 → 步骤计划 → 工具轨迹 → 权限边界 → 结果及引用。

固定工作流
1 collect：get_account_snapshot，读取所选合成情景。
2 diagnose：calculate_funnel，计算指标与异常信号。
3 plan：build_budget_draft，按目标生成 16000 元预算草案。
4 approve：request_approval，等待用户确认本次模拟归档。
5 archive：save_simulated_draft，归档到本次浏览器内存并允许导出。
“专家”是工作职责分区，并非多个模型。自由文本输入仅通过“成本/降本”关键字影响成本优先级；其他任务采用收入优先。工作流不进行任意自然语言推理。

状态与转换
idle → running → waiting → approved/running → completed。
running → failed → retry/running；重试上限一次，复用已完成快照。
waiting → denied/cancelled；拒绝后下游动作不得执行。
running / failed / waiting → cancelled；用户停止后不得继续推进。
completed/cancelled 不得重复执行；新任务 permission 必须重新为 pending。

授权契约
读取合成数据和本地计算无外部副作用，默认允许。
模拟归档需要一次显式确认。授权仅绑定当前 run，不继承到下一次任务。
真实广告投放、费用、平台预算更新完全未接入。
前端状态机只是交互与逻辑演示，不构成生产级安全隔离。真实上线需服务端权限校验、幂等、审计与工具凭证隔离。

故障与恢复
勾选“模拟一次工具超时”会在洞察步骤产生固定失败。失败不会重复读取上游数据，不会跳过授权节点。
重试由用户发起，只恢复当前失败步骤。日志记录上下文：情景、步骤、权限、重试次数。
自动执行延迟用于展示步骤，不代表模型耗时。
停止任务清除当前页面定时调度；真实远程取消与持久化恢复需另外设计。

导出协议
JSON 包含目标、情景、各步骤状态、日志与引用、权限状态、重试次数、指标、建议、预算草案、限制与导出时间。
externalCalls=0；realAccountWrites=0。导出时间为实际导出时刻，其他数据为合成。

FlowDesk 验收
- 正常任务一定停在确认节点，未确认不能归档。
- 拒绝与停止均终止后续工具。
- 超时后重试不重复上游读取，仍要求人工确认。
- 新任务不继承已授权状态。
- 任意输入文本按文本展示或 HTML 转义，不能作为页面脚本执行。
- 结果与日志均可导出，缺少结果时不声称任务完成。

五、评测方法与真实证据

运行：node evidence/product/evaluate.cjs
依赖：Node.js 内置 assert/fs/path；无第三方包。
脚本读取两个页面共用的 product-core.js，运行指标、预算、实验与状态机检查，并写入 evaluation-report.json 与 evaluation-report.txt。
不通过数由真实执行产生；报告保留实际 UTC 时间与 Node 版本。
数学验证采用已知算例、边界、聚合陷阱与不变量；状态机验证越权、拒绝、恢复及授权隔离，而不只镜像实现。
报告不包含 LLM 质量、用户可用性、浏览器视觉验收或线上商业效果。这些验证应在后续分别开展。

六、下一阶段

1. 目标用户任务测试：验证假设与信息架构，记录失败点，不预设满意度结论。
2. 脱敏数据回放：检查归因延迟、退款、异常埋点与预算边际收益。
3. 接入 LLM 前建立基线：引用正确率、数值一致性、任务完成率、不可回答时的处理、越权建议率。
4. 真实工具接入：JSON Schema 契约、服务端授权、幂等键、持久化事件、重试与人工接管。
5. 在受控条件下开展真实 A/B 实验；达成预注册标准后才报告收益。
